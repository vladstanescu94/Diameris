# Full App Audit — 2026-09-27

A full audit of the iOS app (Web/ was out of scope): architecture, Apple skills (SwiftUI,
accessibility, localization, Swift Testing), business-logic placement, tests, and end-to-end QA in
the iOS Simulator. This file is the record: what changed, the proof behind every bug fix, and the
follow-ups deliberately left for later.

**Rule applied to every bug claim:** a test that **fails** with the bug put back and **passes** with
the fix. Refactors, new APIs and cleanups don't need that proof. Purely visual claims (VoiceOver,
Dynamic Type layout, glass) are verified in the simulator instead and marked *UI-only*.

---

## 1. Architecture

**Before:** Onboarding (a feature) depended on Persistence and `@_exported` it, and its view model
wrote SwiftData models. The `MonthlyRecord` `@Model` lived in the Dashboard feature. SwiftData
writes were spread across `MainTabView`, a 710-line `SettingsSheet`, and `DevDebugView`, mostly as
`try?` with errors dropped. Business math was duplicated in feature view models.

**After** (details in [Architecture.md › As Built](./Architecture.md)):

```
Diameris (app) ──► Onboarding, Dashboard, Expenses ──► Domain, DesignSystem, SharedUI, Utilities
      └──────────► Persistence ──► Domain
```

- No feature imports Persistence or SwiftData. Onboarding hands back an `OnboardingResult`
  (Domain) and the app persists it.
- Every write goes through `Persistence/ModelContext+Writes.swift`: one save, rollback on failure,
  errors logged via `Logger.persistence`.
- Money rules live only in Domain: totals, shares, validation, savings boost safety, account-type
  rules, remaining-money destinations, rounding to cents, and shortfall handling.
- `SettingsSheet` is split into `SettingsForm`, `SettingsSavingsSection`, `AccountEditorSheet` and
  shared input components.
- Schema changes are additive only. The existing on-disk store was verified to open with the new
  schema: a store written by HEAD was opened by the new code, all rows read back, and the startup
  repair relinked its broken expense.
- Repository protocols and a `DependencyContainer` are **deliberately deferred**: closures are the
  boundary while no feature touches storage.

## 3. Tests

Suites were rebuilt around real scenarios; tautological tests (asserting defaults, enum raw values,
constants equal to their own literals, getters) were removed.

| Package | Before | After |
|---|---|---|
| Domain | 221 | 62 functions (≈120 cases incl. a 55-case "plan sums exactly to income" invariant) |
| Utilities | 49 | 9 |
| DesignSystem | 10 | 4 (contrast rules) |
| SharedUI | 0 | 2 |
| Persistence | 16 | 28 (in-memory store scenarios) |
| Dashboard | 77 | 16 |
| Expenses | 48 | 12 (+ catalog check) |
| Onboarding | 46 | 37 (+ catalog check) |

**Verification outcome:** every testable bug claim went red with the bug put back. Four claims were
false (the "bug" didn't exist or wasn't visible) and are recorded as such. Two of the audit's own
fixes were incomplete — the onboarding retype crash and the slider snapping — and several tests were
too weak to catch their bug (MonthlyRecord cleanup, the repair's Joint-count guard, a 3.3 multiplier
that happens to be exact, a 1-in-6 transfer-order check). All were fixed test-first.

## 4. Follow-ups (deliberately not done)

### Product decisions
- **F-P1** Savings "Skip for now" still saves the default 25% — relabel to "Use recommended (25%)" or save 0%.
- **F-P2** Onboarding back navigation (the spec asks for it; the flow is forward-only).
- **F-P3** Income maximum (1,000,000 per spec) not enforced.
- **F-P4** Settings can't edit income or add/delete accounts; income only changes through New Month.
- **F-P5** Emergency target follows the latest New Month salary (kept by decision). Better: base it
  on an average of recent months, recorded in the unused `MonthlyRecord`.
- **F-P6** Onboarding offers only 4 preset expenses (no custom/annual); no Utilities/Insurance default category.
- **F-P7** Deleting a custom category that's in use gives no warning.
- **F-P8** Surface `unallocatedRemainingMoney` (destination account missing) to the user.

### Risks
- **F-R1** The startup repair relinks a single dangling expense link to the only Joint account. HEAD's
  onboarding allowed linking to any non-primary account, so a link that pointed at e.g. Personal would
  be moved to Joint. Accepted: Joint was the documented use case, the result is visible and editable
  in the Expenses tab, and a stricter rule would leave a typical store unrepaired.
- **F-R2** Romanian strings added during the audit are machine-translated — needs a native review.
- **F-R3** `.localized` keys are invisible to Xcode's extractor and show as "stale"; never run
  "Remove stale strings". Longer-term: migrate to `String(localized:bundle:)` so keys are extracted.

### Accessibility / UI polish
- **F-U1** Some duplicate unlabeled buttons remain beside onboarding's account-type and "From:" menus;
  some icon-picker buttons read raw SF Symbol names (e.g. "fuelpump.fill").
- **F-U2** New Month step 2 is empty when only a Primary account exists — skip it or show an empty state.
- **F-U3** With only a Primary account, onboarding's Savings step still promises an amount the plan allocates 0 to.
- **F-U4** Slider label mixes "25%" (hardcoded) with locale "5 %".
- **F-U5** At AccessibilityL the Settings currency name truncates; short months show a "+0 RON" Emergency row.
- **F-U6** Glass is applied to content rows (ExpenseRow, AccountRow), which DesignGuidelines discourages.
- **F-U7** CurrencyAmountField nests a glass Menu inside a glass container.
- **F-U8** Expense rows have no VoiceOver delete action (delete is reachable via edit).
- **F-U9** New Month steps dismiss the keyboard with a whole-view tap gesture; SalaryEntryStep has no
  ScrollView at AX5 on small phones.
- **F-U10** Weak scroll-edge effect under the status bar in dark mode at large sizes.
- **F-U11** Account naming differs by screen ("Main" / "Primary" / "Main Account").
- **F-U12** Account names have no length cap (a 60-character name wraps to ~6 lines in rows and plan
  cards); only the user's name is capped at 50.
- **F-U13** An account rename only commits on Return or when another field takes focus; tapping a
  non-focusable area leaves the row in edit mode (standard SwiftUI focus behaviour).

### Tech debt
- **F-T1** Repository protocols / `DependencyContainer` — add only when a feature must query storage itself.
- **F-T2** `DevDebugView` JSON import writes models inline, and its percent display truncates (`Int(pct * 100)`). Dev-only.
- **F-T3** An emergency account without a multiplier takes all savings (business rule to confirm).
- **F-T4** `AmountFormatter.formatForDisplay` hides cents; `TransferPlan.summary` / import errors are English (dev-only).
- **F-T5** `Frequency.monthlyMultiplier` can be deprecated (money code uses `monthlyEquivalent(of:)`).
- **F-T6** First launch logs a harmless CoreData "Application Support missing" recovery.
- **F-T7** Web/Server tests pin the old iOS behaviour (9 fail after the Domain fixes) — Web is untested and out of scope.
